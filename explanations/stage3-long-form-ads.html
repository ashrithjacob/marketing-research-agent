Stage 3 · Long-form ads

How stage 3 finds, reads and analyses ads

An AI agent searches a library of Facebook and Instagram ads and keeps the ads that it thinks are worth studying. Then other AI agents read each kept ad and label it. Three more AI calls group the ads into angles, check each angle against your own claims, and write one finding per step of the page. Code counts everything you see on the page.

Read this first. The scout agent on this page has not run yet. No call from it exists in either database. The three analysis agents (added 2026-10-22) have not run on real data either: they are proven by tests with scripted answers. The ads in the app now came from an older method (see "Before and after"). This page explains what the code does. The ad in the examples is real: it is stored from run 344caa7d (Mullevia mullein drops, US).

What an "agent" is

An agent is an AI model that works in a loop. It can ask for a tool, read the answer, and then decide what to do next. The app gives it the tools and runs them. The model itself only writes text.

The agent stops in one way only: it hands in its answer through a special tool called submit. Code then checks the answer. If the answer breaks a rule, code sends the problems back, and the agent tries again.

What limits stop an agent? How it works
  • Turns. Each agent has a maximum number of turns. The scout has 40. A reader has 4. At the limit, the agent stops.
  • Refusals. Code refuses an answer at most 3 times. After the third refusal, the agent stops.
  • Reminders. If the model writes text but calls no tool, the app reminds it to submit. It does this at most 2 times.
  • Network. If the connection to the model drops, the app continues on a backup model, up to 3 times.

An agent ends with one of four results: completed (answer accepted), invalid (no accepted answer, for example at the turn limit), failed (the model could not be reached) or cancelled (you stopped the run). "Invalid" is not "failed": the agent worked, but its answer broke a rule.

Code words Code

AgentRunner drives the loop on top of the library pi-agent-core. TurnPolicy counts turns and sends the reminders. SubmitTool runs the checks and counts refusals.

How it works How it works

The job description tells the model to act as a growth marketer. It must study four groups of ads, called rings:

3

The scout searches

The scout asks for a search. Code runs it on TrendTrack, pays for each ad that comes back, and shows the scout a short line for each ad.

How it works How it works

The scout chooses four things: the words, where to look (ad text, brand name or website), the order (for example "longest running") and how many ads (1 to 20).

Code adds fixed filters. It asks only for image ads with at least 2,000 characters of text, in the run's countries, active or stopped.

Before the call, code refuses an order that TrendTrack does not accept, and refuses a search after the 20th. A refusal costs nothing.

After the call, code writes the cost to the run, then saves every ad that came back in the scout log. This log is how code can later prove that the scout really saw an ad.

Code words Code

The tool is search_ads (SearchLongFormTool). It calls TrendtrackAds.search, which sends POST /v1/ads/query with mediaType: "image" and minDescriptionLength: 2000. MeteredAdLibrary writes one charges row. ScoutLog.record saves the ads by TrendTrack id and counts the search.

4

The scout reads, and looks at trending shops

The scout can read the full text of any ad it has seen, for free. It can also ask for a list of fast-growing shops, then search their ads.

How it works How it works

A search shows only the first 220 characters of each ad. To read the rest, the scout calls "read ad". Code takes the text from the scout log. Nothing is fetched, so it is free.

"Find trending shops" asks TrendTrack for shops on its trending list, in the run's countries, with at least 20 ads in the last 7 days. It returns shops, not ads. The scout then searches each shop's ads by its website. Each shop costs 4 credits, and each call uses one of the 20 searches.

The scout repeats steps 3 and 4 as it chooses, inside its 40 turns and 20 searches.

Code words Code

read_ad is ReadAdTool; it reads ScoutLog.ad(id). find_trending_shops is TrendingShopsTool, which sends POST /v1/shops/query with displayInTrending: true and adsTimePeriod: "last7d". The shops are not stored.

5

The scout hands in its list, and code checks it

The scout submits the ads it wants to keep, each with a ring and a reason, and the brands it found. Code checks the list against four rules.

How it works How it works

Code refuses the list if:

  1. an ad is not in the scout log (the scout never saw it, or copied its id wrong);
  2. an ad is in the list two times;
  3. the list has more than 150 ads;
  4. more than 15 ads go to the same website.

Code does not check whether an ad is good, or whether its ring is correct. That judgement belongs to the model.

If the scout ends without an accepted list, the stage ends there. The searches are still paid for.

Code words Code

The answer's shape is the schema ScoutReportSchema: kept[] of {ad_id, ring, why} and brands[] of {brand, domain, ring, why}. The four rules are AdScout.problems. A scout result of invalid makes the stage invalid; anything else not completed makes it failed.

6

Code saves the kept ads

Code saves each kept ad to the database, and marks it as a competitor's ad if it goes to that competitor's website.

How it works How it works

Code takes each ad's data from the scout log, not from the scout's answer. So the model cannot change an ad's numbers or text.

An ad is a competitor's when its website matches a confirmed competitor's website exactly ("www." removed). So nz.lignosus.com does not match lignosus.com.

Code saves the ring and the reason next to each ad. The brand list goes out as a run event; no table holds it.

7

Reader agents label every ad

Code splits the kept ads into groups of 8. A reader agent reads each group and labels each ad: who it speaks to, what it claims, and whether it is winning.

How it works How it works

Three readers work at the same time. Each one takes the next group until no groups are left. A reader has no tools and 4 turns. It gets the product, then each ad's numbers and full text.

For each ad it gives: the person the ad speaks to, the claim type, the awareness level, the mechanism, the proof, the offer, the objections, the emotion, risky health claims, and a bucket: winning, testing or dead, with the reason.

Code checks only that each ad in the group has one label, and that no id is new. If a group fails, its 8 ads stay without labels. Nothing tries that group again.

Code words Code

CompetitorAdStage.readAll makes batches of BATCH = 8 and runs concurrency = 3 workers. Each batch is one AdReader.read (agent ad_reader:<n>, MAX_TURNS = 4, schema AdReadingsSchema). The check is AdReader.problems. AdTable.saveReading writes the bucket to ads and the rest to ad_extractions.

8

One call groups the ads into angles

One AI call sees every read ad and puts each one in exactly one angle. Code checks that no ad is left out, placed twice or made up.

How it works How it works

The call gets one line per read ad: its id, advertiser, claim type, mechanism, who it speaks to, and its hook. It hands back 5 to 20 angles. Each angle has a short key, a name, one line on what it claims, and the ids of its ads.

Why one call and not a label from each reader: the readers see 8 ads at a time. Names invented in separate groups would not match. One call that sees every ad keeps the names consistent.

Size, estimated: 190 ads at about 200 characters each is about 10,000 input tokens, about one cent at list price. Not measured: no live run has made this call.

Code words Code

AngleGrouper.group runs agent angle_grouper (4 turns, no tools) with schema AdAnglesSchema. AngleGrouper.problems is the check. AdAnalysisTable.saveAngles writes table ad_angles. The hook comes from HookCutter.cut.

9

One call checks each angle against your claims

A second call reads the claims on your product page and gives each angle one of three answers: you already claim this, you need a new claim, or it does not apply.

How it works How it works

The call gets your product, your claims numbered from 0, and each angle with the hooks of its strongest ads. A "supported" answer must name the claims that back it, by number. Code refuses a number that does not exist, and a "supported" answer that names none.

Code, not the model, then adds the risk share: the part of an angle's proven ads that make a claim the reader flagged as risky under FTC (US Federal Trade Commission) or Meta health rules.

What this does not say: whether you are allowed to make a claim. Stage 1 stores the claims you already make, not a list of permitted ones.

Code words Code

AngleFitter.fit runs agent angle_fitter with schema AngleFitsSchema; verdicts supported, needs_new_claim, does_not_apply. The claims are product.claims_on_page. AdAnalysisTable.saveFits writes fit, fit_claim_indexes and fit_why on each angle.

10

One call writes a finding for each step

Code counts the tables. A third call reads only the tables, not the ads, and writes one sentence for each of steps 2 to 5 of the page. The sentence may not contain a digit.

How it works How it works

Each finding names what it is about (an angle, a label value or a brand), gives one sentence, and names up to six ads. Code checks that every name and every ad id exists.

The no-digit rule is the point. A model that writes "five brands" can be wrong, and code cannot check a number inside a sentence. So the sentence carries the meaning, and the page shows the numbers next to it, counted by code.

If any of the three calls ends without an accepted answer, stage 3 ends the same way ("invalid" or "failed"). The ads and their labels stay saved.

Code words Code

FindingsWriter.write runs agent ads_findings with schema AdFindingsSchema, for STAGE3_STEPS = 2, 3, 4, 5. AdAnalysisStep.analyze runs the three calls in order and stops at the first that fails.

The stage gives its result

The stage writes a one-line summary and ends "completed". It ends "invalid" if no group of ads could be read, or if one of the three analysis calls had its answer refused.

How it works How it works

The summary counts the ads kept, the ads seen, the searches, the trending shops, the brands, the ads in each ring, the ads read, and then the angles, the proven ads and the findings.

Later, if you add competitors to a finished run, stage 3 does not search again and does not call the analysts again. It only marks the ads it already has that go to the new competitors' websites. The page counts competitors when it loads, so its tables update. The findings are not rewritten.

12

Code counts the page, every time it loads

When you open the page, code counts every number on it from the stored ads, angles and findings. Stage 4 and stage 5 also use the ads.

How it works How it works
  • Proven: an ad that is still active, has run 30 days or more, and has 2 or more duplicates. A brand keeps paying for that only while the ad makes money. Code decides it from TrendTrack's numbers. The section "What the page counts" below shows it on real data.
  • Launches: ads first seen in the last 30 and 60 days, against the run's date. An angle is "rising" when most of its dated ads are recent, "fading" when none are.
  • Labels: for each value of each fixed list, its share among proven ads beside its share among the rest. A value on fewer than 5 ads is shown but not ranked.
  • Stage 4 uses the awareness labels. Stage 5 uses only "supply" ads: a competitor's ad, or an ad in the direct-competitor or same-problem ring.

Two limits found while building it How it works
  1. The risk share does not separate angles yet. 189 of the 190 read ads carry at least one risk flag. So every angle shows a risk share near 100%. The cause is how much the reader flags, not the count.
  2. Brand counts stop at 15. The scout keeps at most 15 ads per brand. A brand that runs 200 ads counts as 15 in the brand grid and in "launching now". The planned fix is a paid count per competitor (the "brand census"). It is not built: it first needs one paid test of what TrendTrack's total counts.

Where these prices come from How it works

TrendTrack charges in credits. You pay for the rows that come back, not the rows you asked for. TrendTrack reports the credits of each call in its reply, and the app writes that number to the run's costs.

The app values one credit at $0.0089. That is the plan price: $89 a month for 10,000 credits (operator, 2026-10-03). TrendTrack's documents list extra credits at $1 per 1,000.

Measured on run 344caa7d: the older search method used 540 credits ($4.81) for 40 searches and kept 150 ads. The readers cost $0.42 in 42 calls. One reader call used 28,281 input and 9,957 output tokens, took 75 seconds and cost $0.0092.

Three surprises in the real data How it works
  1. "Days running" is not one ad's run time. TrendTrack groups copies of the same picture and text. For a group, it counts from the oldest copy's start to today. The Lignosus ad was seen from 2025-05-07 to 2025-10-09 (155 days), but shows 530 days. 28 of the 207 stored ads show this gap. The scout's "30 days" rule and the readers' bucket both read it as one ad's time.
  2. No stored ad has an audience. Age and gender are empty on all 207, so the scout sees "audience unknown".
  3. Active ads have a last-seen date. All 90 active ads have one. TrendTrack's documents say it should be empty while an ad runs.

Why the change was made How it works

On run 344caa7d, the sweep's one-word search terms brought in dental ads and pet ads. A word match is not relevance. The sweep also paid for 540 rows to keep 150 (workings.md, docs/gaps.md 13a).

The house rule is: the agent judges, and code checks anything that code can check. Code can prove the scout saw an ad and stayed inside the limits. Code cannot judge whether an ad speaks to your buyer. So that judgement went to the agent.

The option not taken: keep the code sweep and add better keyword lists. The repo refuses lists of words in code (a "synonym table"), because each new product needs new lists.

Check your understanding

Three questions

The scout submits an ad id that it made up. What happens?

Code refuses the list, because that id is not in the scout log. The agent gets the problem with a number and can try again. After 3 refusals it stops, the stage ends "invalid", and no ads are saved. The searches are still paid for.

Can the scout change an ad's text or its days running?

No. The scout's answer has only the id, the ring and a reason. Code takes the ad's text and numbers from the scout log, which holds what TrendTrack returned.

The findings writer writes "Five brands run this angle, and 3 are competitors." What happens?

Code refuses it, because the sentence has the digit 3. ("Five" is a word, so only the 3 breaks the rule.) The agent gets the problem and tries again, at most 3 times. If it never passes, stage 3 ends "invalid", but the ads, labels and angles stay saved and the page still shows every count.

Words used on this page

Glossary

Agent
An AI model that works in a loop: it asks for tools, reads the results, and ends by handing in an answer.
Turn
One pass through the AI model: it reads everything so far and replies once.
Tool
An action that the app performs for the model, for example a search. The model asks; code does it.
Submit
The one tool that ends an agent. Its input is the final answer.
Check
Code that tests a submitted answer and lists its problems. An empty list means accepted.
Schema
The exact shape an answer must have. Code rejects an answer that does not fit.
System prompt
The fixed instructions an AI model gets before its task.
Scout
The agent that searches TrendTrack and chooses which ads to keep.
Scout log
The app's record of every ad the scout's searches returned. Code checks the kept list against it.
Reader
An agent that labels a group of 8 kept ads. It has no tools.
Ring
One of four groups for a kept ad: direct competitor, same problem, same buyer, trending shop.
Supply ad
An ad that competes for your buyer: a competitor's ad, or one in the direct-competitor or same-problem ring.
Bucket
The reader's judgement: winning, testing or dead.
Proven
An ad still active after 30 days or more, with 2 or more duplicates. Code decides it. It means scaled and kept running, not known to be profitable.
Angle
The core argument an ad makes: the promise, the reason to believe it, and who it is for. One AI call groups every read ad into one angle.
Hook
The opening of an ad: its first sentence or first line, whichever is shorter. Code cuts it from the text.
Fit
Whether your own claims back an angle: supported, needs a new claim, or does not apply.
Finding
One sentence per step of the page, with no digits. The numbers beside it come from code.
Risk share
The part of an angle's proven ads that make a claim the reader flagged as risky under FTC or Meta health rules.
Credit
TrendTrack's unit of payment. One returned row costs one credit, valued at $0.0089.
Duplicates
How many copies of the same ad TrendTrack found. Advertisers copy ads that make money.
Reach
Meta's public count of how many times an ad was shown. Meta publishes it mainly for ads shown in the EU and UK.
Invalid / failed
Invalid: the agent finished, but no answer passed the checks. Failed: something broke, for example the model could not be reached.
pi-agent-core
The open-source library that runs the model-tool loop.
