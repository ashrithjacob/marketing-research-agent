Stage 3 · Competitor long-form static ads · as built 26 Oct 2026

How stage 3 finds and reads the market's ads

Stage 3 now takes the market's top long-form ads for the product's ingredient, about 350 for mullein, and reads each different ad text once. Before, an agent chose its own searches and kept 5 ads.

Status. The pool and the reading ran for real on the Mullevia run on 26 Oct. The run then stopped at the angle grouper. That step is now rebuilt and passes its tests, but it has not run on real ads yet.

1 · Where this lives

The parts stage 3 uses

Stage 3 is one class, CompetitorAdStage. It calls one outside service for ads (TrendTrack), one for the LLM agents (OpenRouter), and the database. The cockpit page only reads what stage 3 stored.

3 · Follow one ad through stage 3

The real data at every step

This section follows one real ad from the Mullevia run, step by step. It shows what goes into each step and what comes out, as the app stores it. Long texts are cut with "…". All values come from run 344caa7d on 26 Oct 2026, unless a step says otherwise.

The ad: TrendTrack id facebook_1042909135255527. It sends people to a mullein inhaler called Balanlogy. It is one of 75 ads with the same text.

Step 1Find the search word

Stage 1 has already stored the client's product. Stage 3 reads two of its fields.

FieldValueWords code takes from it

Code keeps only the words the two fields share, so the search word is mullein. If they share no word, code searches the whole ingredient name. That matters: TrendTrack matches a phrase as a whole. On 26 Oct "Mullein Leaf" matched 411 US long-form ads, and "mullein" matched 3,464.

Step 2Ask TrendTrack for ads

TrendTrack is a paid service that records ads running on Facebook and Instagram. The app sends it a question as JSON (a text format of names and values) and gets JSON back. This is the first of the 8 questions, as the app builds it (adapters/trendtrack-ads.ts:32-47):

}
  1. The word to look for.
  2. Look for it in the ad's text, not in the brand name or the web address.
  3. The order of the answer. Stage 3 asks four times, with four orders (table below).
  4. Include ads that stopped running, not only live ones.
  5. Only ads shown in the run's markets. Here, the US.
  6. Only image ads, no videos.
  7. Only ads with 2,000 or more characters of text. This is what "long-form" means here.
  8. 50 ads per page. Code asks for page 1 and then page 2.

TrendTrack answers with a list called data (the ads) and a block called pagination. It also sends a header, x-credits-used: 75, which says what the page cost: 1.5 credits per ad. The app stores that as one charge: 75 credits, $0.67.

Step 4Store the ad and give it a bucket

The store saves all 351 ads as rows in the ads table. For each ad it does two more things:

  • Competitor link. If the landing domain is the web address of a confirmed competitor, the row gets that competitor's id. revibezen.us is not one, so our ad has none. Only 3 of the 341 kept ads link to a confirmed competitor.
  • Bucket. Code reads the ad's own numbers and sets bucket and bucket_why.
Ad (same text, different pages)DaysStatus7-day reach growthCopiesBucket, and the reason code writes
SoyJackツ → revibezen.us (our ad)45inactive014winning ran 45 days
Arvea Chez Vous → dermanuvita.com5inactive121dead stopped after 5 days
Weekend health routine → heyzeyla.us1inactive?19dead stopped after 1 days

The rule, in order: 10 or more days is winning. Otherwise, a stopped ad is dead. Otherwise, a running ad with 400+ new reach in 7 days or 5+ copies is winning. Any other running ad is testing. The second row has 21 copies but stopped after 5 days, so it is dead. Copies count only while an ad still runs.

In the whole run: 226 winning, 13 testing, 102 dead.

Step 5Put ads with the same text into one script

Code makes a key from each ad's text. It changes every letter to lower case and removes everything that is not a letter or a number:

"I'm pissed nobody told me about this sooner.\n\nBecause I almost…"
   → "impissednobodytoldmeaboutthissoonerbecauseialmost…"

Ads with the same key form one script. Our ad's script has 75 ads. They ran from several pages (SoyJackツ, Claudio Rivera, Arvea Chez Vous and others) to three shops: revibezen.us, heyzeyla.us and dermanuvita.com. 68 are winning and 7 are dead. 351 ads made 161 scripts.

The first ad of each script, in the store's order (most days first), is the one the reader sees. For this script it is facebook_1553160189171683, also from SoyJackツ, 45 days.

Step 6The reader agent reads the script

The reader is an LLM agent. Code sends it 8 scripts per call, and runs 3 calls at the same time. Each call gets one text, built by code (agent/stages/ads/ad-reader.ts). It starts with the client, then one block per ad:

The client: Mullevia Mullevia Mullein Drops, a lung-support supplement (liquid
herbal extract) sold on Mullein Leaf. Its claims: Powered by maximum-potency
mullein extract, … | …

<ad id="0684fb1aa848466c9d3df0f653b6329c">
advertiser: SoyJackツ; lands on https://www.revibezen.us/products/lungcleansingpen18_en/up; audience all, ages 18-65
I'm pissed nobody told me about this sooner.
…the whole text of the ad…
</ad>
<ad id="…"> …7 more ads… </ad>

The id in <ad id=…> is the app's own id for the row, not TrendTrack's. One call of this kind was 90,197 characters long. The reader sees no days, reach or copies, because it does not judge how the ad is doing.

The reader answers by calling a tool named submit, with one reading per ad. This is the reading it gave our script, as stored:

{

                is destroyed by stomach acid …",
  "proof_kinds": ["testimonial", "results_timeline", "social_numbers"],
  "offer_kinds": ["discount"],
  "offer": "Balanlogy mullein inhaler with 50% off.",
  "emotion_kind": "frustration",
  "landing_kind": "product_page",
  "copy_structure": "personal_story",
  "risk_flags": ["'lung function is up 11%' attributed to mullein inhaler", …]  ⑤
}
  1. Ring: how the ad relates to the client. Here: the same kind of product on the same ingredient.
  2. Avatar: who the ad speaks to, in one sentence. Stage 5 uses this when it places ads on its avatars. (COPD = chronic obstructive pulmonary disease; FEV1 = a lung-function measure.)
  3. Claim type: plain, bigger, mechanism (a reason why it works) or identity.
  4. Awareness: what the opening assumes the reader already knows. "Solution aware" means they know solutions exist, such as mullein tea.
  5. Risk flags: claims that look risky under advertising rules for health products.

Code checks the answer before it accepts it. Every ad in the batch must have exactly one reading, no reading may name an ad that was not sent, and every list value must come from the fixed lists. If a check fails, the agent gets the problems back and tries again, up to 3 times. In this run, 20 of the 21 batches passed. One batch failed because the model sent its list as text in quotes. Code now turns such text back into a list before it checks.

Step 7Copy the reading, and drop off-market ads

Code copies the reading of the first ad to all 75 ads of the script. Each of the 75 rows now has the same ring, avatar and claim, but keeps its own days, reach and bucket.

When the reader marks a script off_market, code deletes all its ads from the run. Two kinds came up in this run. These are the reader's own ring_why lines:

  • "Sells Weston Animal Co Airway Support chews with mullein leaf for dogs (Yorkie tracheal collapse) …"
  • "Sells an herbal nicotine-free breathing stick (mullein, thyme, peppermint) to help 64-year-old smokers quit …"

10 ads were dropped. 341 stay: 284 direct competitor, 36 same problem, 5 same buyer, and 16 with no reading because their batch failed.

Step 8Group the scripts into angles

An angle is the core argument a group of ads makes. One agent call gets one line per script, with a short handle. For our script, code would build this line (angle-grouper.ts:41-45):

[s1] 75 ad(s), SoyJackツ | mechanism | mechanism: Two mucus layers with a cemented deep
layer; … | for: A COPD patient on inhalers watching FEV1 decline … | "I'm pissed nobody told me about this sooner."

The text in quotes is the hook: the first sentence or the first line of the ad, whichever is shorter. Code cuts it, so the model never retypes it. The agent answers with angles, each a key, a name, one line, and the handles of its scripts. Code checks that every handle is in exactly one angle, then puts all 75 ads of s1 on that angle.

This step is rebuilt. It has not run on real ads yet. On 26 Oct the old version, one line per ad, failed here.

Step 9Fit, findings, and what later stages read

  • Fit. One agent gets each angle with its best hooks and the client's own claims, numbered. For each angle it says supported (and cites claims), needs a new claim, or does not apply.
  • Count. Code counts the tables: ads and proven ads per angle, launches in the last 30 and 60 days, which labels proven ads use more than the rest.
  • Findings. One agent gets only those tables, not the ads. It writes one headline for each of steps 2 to 5 of the ads page. Code refuses a headline with a digit in it, so every number on the page comes from code.
  • Stage 4 reads the stored ads when it judges the market's awareness and sophistication.
  • Stage 5 uses only ads from a confirmed competitor or in the direct-competitor or same-problem ring (ads.ts:111-114). It places them on its avatars, and counts the share of each avatar's ads in the winning bucket. Our ad is direct competitor and winning, so it counts.

  1. Code splits the product name and the key ingredient into words, and keeps the words they share. "Mullein Leaf" and "Mullevia Mullein Drops" share "mullein".
  2. If they share no word, code searches the ingredient as written. TrendTrack matches a phrase as a whole, so this finds fewer ads.

How code decides an ad is doing well

server/src/domain/ads.ts:92-106
static readonly WINNING_DAYS = 10;
static readonly TRACTION_REACH_7D = 400;
static readonly TRACTION_DUPLICATES = 5;

static of(hit) {
  if (days >= 10) return { bucket: "winning", … };        ①
  if (hit.status !== "active") return { bucket: "dead", … }; ②
  if (reach >= 400 || duplicates >= 5) return { bucket: "winning", why: "early traction…" }; ③
  return { bucket: "testing", … };                       ④
}
  1. An ad that ran 10 days or more is winning, whether it still runs or not.
  2. An ad that stopped before 10 days is dead.
  3. A young ad that still runs is winning when its reach grew by 400 or more in 7 days, or the advertiser copied it 5 or more times.
  4. Any other young ad that still runs is testing. The store calls this rule for every ad when it saves it (ad-table.ts:20).

5 · Why it was built this way

The design reasons

ChoiceWhyWhat was not taken
Code pulls the adsThe scout agent made 17 searches. 13 returned nothing: competitor domains with no long-form ads, and phrases. It asked for 5 of the 3,637 ads its one useful search found.Keep the scout and tell it in the prompt to search more. A prompt rule does not stop the same mistake from happening again.
Read each script onceThe same text often runs many times from several pages. In this run one script ran as 75 ads. 351 ads held 161 scripts.Read all 351 ads. That costs more than twice the reader calls for the same answers.
Code sets the bucketA reading is copied to every ad of its script, but each ad has its own days and reach. So the bucket must come from each ad's numbers. The 10-day line is the owner's rule.Let the reader judge each ad's bucket. Then a copied reading would carry the wrong bucket.
Drop off-market adsAn ad can mention mullein and sell to someone else, such as dog-cough chews. 10 ads were dropped in this run.Keep them in a separate group. The owner chose to drop them for now.
Group scripts by handlePlacing 341 ads by 32-letter id in one call failed. The model left ads out and once hit the 40,000-token limit.Split the grouping across several calls. Then two calls could invent the same angle under two names.

Two rules for "doing well". The bucket (10-day rule) feeds stage 5: the share of an avatar's ads that are winning. The ads page's analysis uses a stricter rule called proven: still running, 30 or more days, 2 or more copies (extract/proven-rule.ts:9-12). The two rules give different counts. They are not joined yet.

7 · Check your understanding

Three questions

A product is called "Lung Clear Drops" and its key ingredient is "Mullein Leaf". What does stage 3 search for?

The name and the ingredient share no word. So code searches the phrase "Mullein Leaf" as written. On 26 Oct that phrase matched 411 US long-form ads, where "mullein" alone matched 3,464. The pool is then smaller.

The same ad text runs from three pages. How many times does the reader read it, and do the three ads get the same bucket?

The reader reads it once. Code copies the reading to all three ads. The buckets can differ, because code computes each bucket from that ad's own days, status, reach and copies.

An ad started 5 days ago, still runs, and has 6 copies. Which bucket is it in, and does the ads page call it proven?

It is winning: it still runs and has 5 or more copies. The ads page does not call it proven, because proven needs 30 or more days.

8 · Words used on this page

Glossary

Long-form static ad
A Meta image ad with 2,000 or more characters of text (MRA_AD_MIN_COPY_CHARS).
Pool
The set of ads code pulls from TrendTrack for one run: up to 100 ads under each of four sorts, each ad once.
Sort
The order TrendTrack returns ads in. Stage 3 uses four: longest running, most duplicated, reach, and reach growth in 7 days.
Script
A group of ads with the same text, after capital letters, spaces and punctuation are ignored.
Reading
What the reader agent records about one script: ring, who it speaks to (avatar), claim type, awareness, proof, offer and more.
Ring
How an ad relates to the client. Direct competitor: same product. Same problem: another product for the same need. Same buyer: another need, same person. Off-market: sells to someone else.
Bucket
Winning, testing or dead. Code sets it from the ad's days running, status, reach growth and copies.
Proven
A stricter label on the ads page: still running, 30 or more days, 2 or more copies.
Angle
The core argument a group of ads makes: the promise, the reason to believe it, and who it is for.
Agent
An LLM that works in turns and ends only by calling submit. Code checks the submission and can refuse it.
LLM
Large language model. Here: GLM-5.3-flash on OpenRouter, with DeepSeek as a backup.
Credit
TrendTrack's billing unit. It billed 1.5 credits per ad returned; one credit costs $0.0089.
